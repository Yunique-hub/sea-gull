# 1.0.10 市场、工具与 AgentTeams 整合分析

日期：2026-10-25。验证宿主：官方 Windows x64 Harness 0.2.1-rc.3；引擎：dsh-purge 1.1.78；市场：plugin 0.4.16 / core 0.4.13。

## 完成标准与边界

1. 市场已安装 `plugin` 的真实校验返回 live；技能能在桌面对话以菜单和直接 `/distilly` 两种方式注入正文。
2. 首次安装明确选择工具目录，更新保留选择；环境适配原生选目录、一键安装可用工具、哈希校验、路径保存、再次执行和重启后识别通过。驱动及缺少官方二进制的项目必须如实显示待处理。
3. 中文请求与英文资料混合时仍用中文答复，明确要求英文时使用英文；用户自定义人格文件逐字节保留。
4. 工作区对话输入 `agent-teams` 自动创建两个独立成员；成员各自真实执行文件操作，复核依赖分析完成，报告与存档可查。
5. 自动化检查、真实桌面与重启验收后才提交推送；私密配置、原始会话、凭据、项目数据库和测试工作区留在本地。

## 当前项目结构与问题归因

海鸥负责安装、更新、提示词与针对宿主的兼容修改，purge 提供运行时补丁及演练台；市场是独立依赖。不能把市场 core 当作 purge 源文件替换，或通过复制整套旧宿主来兼容。安装器已有运行文件校验，本次将同样的机制用于 AgentTeams。

市场实际安装的包为 `@dsh-market/plugin`，目录项名称却是 `plugin`，且市场元数据缺少可提取 npm 名称的 homepage。原 `resolveInstallName()` 回退短名称，校验在 profile 中找不到依赖。修复先查精确名称，再在当前 profile 中寻找唯一、包清单名称相符的 scoped 依赖；多候选时保持未解析。兼容补丁仅用于已验证的 core 0.4.13，不猜测其他版本。

已存在的技能在新会话可以调用，但在同一会话复现了新装技能不可见：原生后端已经发现新技能，`/` 菜单仍返回旧缓存。原因是宿主技能注册表发出 `skills/change`，远端事件白名单没有转发，前端技能目录也没有订阅它。新增 #93、#94 两条小范围补丁接通该链路；所有原生技能共用这一刷新机制，不逐个添加技能名或界面插件命令。

修复后，两个不同测试技能在已打开的同一会话中随安装出现并可调用；卸载后消失。菜单与直接 slash 调用都由宿主注入实际 `skill-invocation` / `<skill_content>` 正文。保留技能自己的 user-invocable 和模型调用策略，不强制把禁止用户调用的技能开放。市场验证同时要求存在 SKILL.md，不再仅凭目录存在报告 live。缺少标准技能文件的仓库不能伪报为可调用。

英文回复增加独立 `seagull:response-language` 提示段，默认中文，用户明确指定其他语言时按指定范围生效。英文技能、工具日志和协作协议不改变默认语言。不重写用户人格，不翻译代码、命令及原始报错。模型内部推理或工具原始内容仍可能包含英文；这不等于中文自然语言答复的程序化保证。

## 工具安装方案

- Windows `-ToolkitDir`、Bash `--toolkit-dir` 或交互输入设置目录；非交互首次安装缺少设置时停止，不静默选默认盘符。更新不要求重填。
- 环境适配使用 Harness 原生目录选择器；其他宿主没有该能力时允许手填绝对路径。
- 先扫描所选文件夹并保留现有路径，随后补齐缺失工具。GitHub 下载地址、版本、大小及 SHA-256 冻结在 `tool-releases.json`。
- ZIP/TAR 解包拒绝路径越界、符号链接和设备文件，限定展开大小，暂存校验成功后才发布安装目录；失败只清理本次新建暂存目录。
- frpc/frps 共用一个 frp 发布包。Impacket 固定 0.13.1，在所选目录新建独立 venv，不改系统 Python。
- 任务提供逐项进度、失败和待处理说明。运行中的磁盘记录在重启后显示中断，可以重新执行；成功项按已有路径跳过。
- Nmap Windows 官方安装涉及驱动，保留官方安装指引；Masscan 上游 1.3.2 没有官方 Windows 发布文件。两项不会被报告为安装成功。

本机原有 5 项保留，最终识别到 13/15，7 个新增 Windows 程序均能启动并显示帮助/版本，独立 Python 环境能导入 Impacket 0.13.1。fscan 的 `-h` 是主机参数，返回用法和退出码 2；不能把该退出码当扫描失败或执行过扫描。本次没有对网络目标执行扫描。

官方来源：[Nmap 下载](https://nmap.org/download.html)、[Masscan 1.3.2](https://github.com/robertdavidgraham/masscan/releases/tag/1.3.2)、[Impacket 0.13.1](https://pypi.org/project/impacket/0.13.1/)，其他程序见版本清单中的各项目官方 GitHub release。

## AgentTeams 上游分析与整合取舍

上游：[NanmiCoder/dsh-agent-teams](https://github.com/NanmiCoder/dsh-agent-teams/tree/230958db812ed34bcf2d1168e8157bbf5af04055)，版本 0.1.26，MIT，作者程序员阿江（Relakkes）。vendor 保存运行 JS、类型、前端、内置团队资源、原始许可证和说明，作为固定运行快照；完整 TypeScript 源码与开发构建工具见固定上游提交。

上游已具备队长工具、成员协调、任务依赖图、消息、调度、运行监视和每工作区 `.agent-teams/` 状态。复用这些能力比重造调度器更直接。运行需要宿主提供的 `@deepseek-ai/*` 服务，不另起模型服务，不复制账号或凭据。原始上游 smoke 在本机 rc.3 通过，随后以整合运行快照进行真实多成员验收。

最小差异：

| 位置 | 改动 |
|---|---|
| `lib/command.js` | 支持裸命令及 slash；激活说明默认完整计划 automatic，用户明确先审阅时 required；默认中文 |
| `lib/index.js` | 团队 usage 提示同步自动执行与中文报告约定 |
| `package.json` | 加入海鸥托管、上游提交标记及 rc.3 peer 兼容范围 |
| 安装器及 `managed_teams.py` | 固定快照部署、profile bundle 挂载、运行副本逐文件校验；卸载摘除挂载但保留工作区与插件恢复文件 |

没有改变成员工具过滤、上游终止/恢复机制、任务依赖检查及质量审核工具。默认自动批准只针对团队计划；明确的用户先审阅要求仍然有效。已存在团队时优先检查并继续，不重复创建同名成员。
