## 两项适配修复

1. **重复本体挂载**：上游自愈默认向用户 profile 追加 insert，但海鸥 bundle 已经插入本体。新增用例先复现 `wrote=true`，修复后检测实际加载包的海鸥托管标记和 bundle insert，已有本体时不写第二份；缺失本体时继续上游自愈。
2. **跨 profile 改写**：桌面验收的数据比对发现，上游启动扫描其他历史 profile 并追加配置。新增用例复现两个 profile 都被改写；修复后 `DSH_PROFILE` 明确指定时只处理当前 profile。已恢复受影响的旧验收配置，并在真实客户端重启后确认哈希仍与备份一致。未指定 profile 的显式全量调用保留原行为。

对应回归位于 `tests/upstream-1182.test.mjs`。上游 36 项测试纳入 Windows/Linux CI，避免后续只运行海鸥自身回归。

## 本机部署中的 pnpm 限制

首次执行真实 `install.ps1 -Update -Profile desktop` 时，Harness 内置 pnpm 11.28.5 返回 `ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY`，安装器正确非零退出。不是缺少 pnpm：现有 node_modules 记录的 store 与当前 pnpm 解析的 store 路径不同，触发重建目录确认。用户确认另一个磁盘上的 `.pnpm-store` 是缓存目录，并非 pnpm 程序目录。

本次上游未增加运行依赖，因此保留现有依赖目录与所有缓存，使用安装器 `-NoPnpm` 完成文件部署，再调用已有 purge/AgentTeams 同步工具，逐文件核验加载副本并完成真实客户端验收。没有把 pnpm 失败算成成功，也没有自动迁移全局 store 或强制清空 node_modules。一般用户的完整在线依赖重建路径仍需在其实际环境验收；本机此次结论是文件更新与现有依赖组合通过。
